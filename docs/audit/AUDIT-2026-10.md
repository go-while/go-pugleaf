# go-pugleaf audit, October 2026 (base testing-001 @ 84c2081, branch plan-nntp-audit-tests @ cc49dab)

Plan `nntp-audit-tests` (`.claude/plans/wip/nntp-audit-tests.md`) reviewed the code base in eight audit slices
(wave 1) and wrote an NNTP server test suite in six test slices (wave 2). The audit slices read their scope files in
full, traced every seed finding of the plan, fetched the RFCs they cite from rfc-editor.org, and ran repros
against scratch data only (temporary `zz_audit_*` tests on the wave-0 harness, standalone programs under
`./data-test-audit-<slug>/`, scratch builds); nothing touched `./data`. The static-analysis tools were `go vet`,
staticcheck 2026.2.1, golangci-lint 2.14.0 (`--no-config -E gosec`) and govulncheck v1.9.0
(`docs/audit/tools/`). The test slices added 74 `Test`/`Fuzz` functions (81 including the wave-0 harness self-tests and the two
`TestMain`s) in `internal/nntp/nntp-server-*_test.go` and `cmd/nntp-server/{server_e2e_test.go,
e2e_binary_test.go}` (plus `scripts/test-nntp-server.sh`); every
assertion states the RFC-correct behavior, and code that differs is marked with `knownBug(t, <id>, err)`
(§10). This report deduplicates and ranks the findings; the slice reports hold the evidence, so each finding
gets one line here.

Slice reports:
- [audit-nntp-rfc.md](audit-nntp-rfc.md): server command handling against RFC 3977/4643/4644/4642/2980/6048
- [audit-nntp-sec.md](audit-nntp-sec.md): server security, DoS, concurrency, auth cache, TLS, shutdown
- [audit-intake.md](audit-intake.md): article validation, injection, history, header rebuilding (RFC 5536/5537)
- [audit-db.md](audit-db.md): delta database audit after WSH/LO/FU
- [audit-nntp-client.md](audit-nntp-client.md): outbound client, pool, transfer, demuxer, peering
- [audit-web.md](audit-web.md): delta web audit after WSH/LO/FU
- [audit-tools.md](audit-tools.md): fetcher, analyze, importers, tcp2tor
- [audit-ops.md](audit-ops.md): binaries, destructive tools, scripts, CI, `php/`
- [README.md](README.md): report schema, id rules (K6), seed tables; [tools/](tools/): raw tool output

Short report names used below: rfc, sec, intake, db, client, web, tools, ops. Cross-references to the merged plans
use `WSH:`, `LO:` and `FU:` ids (`.claude/plans/done/`). Section numbers count the `##` headings in order (§1 is

(command, code) rows, 31 are marked as violations. They fall into six groups:
- internal faults answered with 500, 503 or 411 instead of 403 (A-nntp-rfc-4);
- variant and permission codes: 500 for MODE/AUTHINFO variants, 502 for POST and for IHAVE/TAKETHIS without a
  processor, 436 for permanent or garbled IHAVE rejects (RFC-5);
- article selection and ranges: 501 for the third form, 502 for numbers ≤ 0 (RFC-3); empty or reversed XOVER/XHDR
  ranges (RFC-6);

  the message-id are rated weak, not wrong).

Every other code the server sends is allowed for its command.

## Decisions for the fix plans

Policy questions the reports defer; each fix plan has to state its choice.

1. **Reads without auth (SEC-5 scope).** Stay a public reader (anonymous reads, with the limits of §6), or add a
   `require-auth-for-reading` option. This decides whether SEC-2, SEC-7 and A-nntp-sec-4 remain unauthenticated
   surface. Plan: nntp-server-hardening.
2. **Hide/spam gating on NNTP and the web.** What `hide` (and `spam`) means for non-admins; A-nntp-sec-2 (NNTP) and
   A-web-1 (web) must apply the same rule (one predicate in the read queries, or hide-aware variants). Plans:
   nntp-server-hardening and audit-delta-fixes.
3. **XHDR value rules (RFC-6).** For an absent header, RFC 3977 §8.5.2 wants a line with an empty value (`n` or
   `n `); the INN-style `n (none)` is also accepted by the tests. Choose one. For headers the server does not index,
   choose between serving them from `headers_json` and answering 503 as §8.5.2 allows for HDR. Plan:
   nntp-server-hardening (and nntp-rfc-commands for HDR).
4. **Unknown-group policy on intake.** Reject (441 POST, 437 IHAVE, 439 TAKETHIS) and never auto-create, or keep
   auto-creation for peer feeds behind an explicit flag (`-accept-unknown-groups`). Also: inactive and `n`/`x`
   groups (A-intake-8). Plan: nntp-intake-injection.
5. **Injection (INT-1).** Message-ID format (proposed `<base32(random 16)>@LocalNNTPHostname`), Date (RFC 5322,
   `+0000`), Injection-Date only when one of them was generated, Injection-Info contents (posting-account hash, e.g.
   `ComputeHashedUsername`), and the Path policy (the served Path is the stored prefixed Path with `!.POSTED` for POST
   and `.SEEN.` for IHAVE/TAKETHIS). Whether web posts' `X-pugleaf-Trace` becomes Injection-Info (INT-7). Plans:
   nntp-intake-injection, audit-delta-fixes.
6. **Control messages, cancel and Supersedes (INT-4).** Honour, ignore, or honour only from the same poster or
   injecting host; store control messages in `control.*`. Plan: nntp-intake-injection.
7. **Plaintext AUTHINFO: drop the advertisement by default, keep 483 opt-in.** A default 483 breaks every
   plain-TCP login, including the harness, the e2e tests and `scripts/test-nntp-server.sh`, so 483 must be a config
   switch that defaults off until STARTTLS exists. `TestAuthPlaintextNotOffered` accepts either 483 or "`AUTHINFO
   USER` not advertised" on a default non-TLS server, so the fix must stop advertising `AUTHINFO USER` in
   CAPABILITIES on plaintext by default (RFC 4643 §2.1) while still accepting the command; then the SEC-5 marker
   can be removed and the assertion kept. Plan: nntp-server-hardening.
8. **SEC-6 must re-check the stored hash on a cache hit.** The auth cache is per process and passwords change in
   `cmd/web` or `cmd/nntpmgr`, so Appendix B's first option (invalidate inside `UpdateNNTPUserPassword` and friends)
   never reaches `nntp-server`'s cache. Store the bcrypt hash (or `updated_at`) at `Set` and compare it on `Get`.
   Plan: nntp-server-hardening (nntp-auth-db).
9. **BUG-7 / SEC-3: drain the article before closing.** If the server closes on "too large" and then writes, the
   client sees a reset and the 441/436/439 is lost (the e2e test shows the write to a closed socket). Read and
   discard up to the terminator (with a byte bound), then reply; close with 400 only when the bound is exceeded.
   Plans: nntp-server-hardening, nntp-intake-injection.
10. **First registered user becomes admin, plus WEB-1.** The user-ID-1 admin rule with registration on by default
    means that an install reachable before the operator registers gives `sh -c` cron access to whoever registers
    first. Decide: admin only via `usermgr`, registration off until an admin exists, and whether `-edit-cronjobs`
    gates enabling only or disabling too. Plan: audit-delta-fixes.

Also deferred by the reports: the past-date cutoff for POST and whether the fetcher keeps lenient dates for archives
(INT-3, A-intake-7); whether `/api/thread-tree` stays (A-web-11); whether the From filter should hide addresses at
all (A-web-6); delays as a config key or token bucket (BUG-3); advertising READER only once DATE/NEXT/LAST/NEWGROUPS
exist (RFC-1/RFC-2).

## Corrections to the plan's slice text

So that wave 4 does not inherit them:
- **test-nntp-overview, "an absent header → `n (none)`":** RFC 3977 §8.5.2 wants an empty value (`n` or `n `);
  `(none)` is INN style. The slice text misread RFC 2980.
- **test-nntp-article, "an empty body gives exactly `\r\n.\r\n` after the headers' blank line":** it is
  `\r\n.\r\n` after the last header line's CRLF (the blank separator line plus the terminator).
- **INT-6:** every batch of an auto-created group skips the history adds, not just the first (A-db-1 makes every
  later `MainDBGetNewsgroup` fail).
- **BUG-2:** the clamp limits the article-number range (start+1000), not the row count; a sparse range can return
  no rows at all.
- **CLI-1:** three parts: two Path header lines carrying three copies of the path, folded Newsgroups continuation
  lines sent again, and a dropped final empty body line (formerly A-nntp-client-8).
- **SEC-2:** the fetcher is not a trigger (bulk mode); the triggers are LISTGROUP and non-bulk intake.
- **Appendix B, `nntp-auth-db`:** only the re-check-on-hit option works (§11 item 8).
- **INT-5:** numbers are reused only when the highest-numbered rows are deleted (expiry of the newest number, admin
  delete), not by plain oldest-first expiry.
- **CLI-2:** affects `nntp-fetcher` only, rated high, not critical.
